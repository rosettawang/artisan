Execution order

The dependency-safe order — who shares a file, what needs what — derived from meta, not remembered. The hand-written Bottlenecks answer the different question of what is worth doing first; when they disagree, priority wins and this block constrains it.

Decisions waiting on the owner

Choices only the owner can make — answer in any Claude session (in chat, or edit the spec's spec-decision meta). A session records the answer in the owning spec and the next prune drops it from here. It never silently picks a default and buries it in a commit.

Bottlenecks

Hand-maintained. What is worth doing first, as opposed to what the dependency graph permits.

  • Nothing here is proven against a moving roast. Every temperature claim was measured on a machine sitting at room temperature. The interlocks have never refused a real command during a real roast. Prefer the phases that get to a watched, beanless heated run soonest over the phases that add tools.
  • The write path is the whole risk. Reads are free and reversible; a burner command is neither. Hardware-pass row 3 gates more than it looks like it does — until one write is observed, every actuator behaviour in both specs is inference from artisanlib/kaleido.py.
  • Rebase cost compounds. The longer this fork sits behind upstream, the more each spec's spec-touches hurts. Pull upstream before starting a phase, not after.

On a machine reporting Fahrenheit, a Celsius ceiling would be checked against an unlabelled number. Code won. How specs get worked

Reference

Conventions — the metadata a spec declares
MetaMeaning
spec-statusopen | blocked | done | canonical. Required. prune deletes the done ones and logs a dated completion note.
spec-touchesSpace- or comma-separated paths the spec edits. Drives conflict detection and ordering. In this fork it doubles as the rebase-cost estimate.
spec-needsSlugs that must land first.
spec-blockerOne dated line of what remains. If nobody can unblock it, it is parked — say so.
spec-decisionOne per owner choice, with the recommended answer and whether it blocks. Never bury a choice in blocker prose.
spec-verifyA shell command that exits 0 when the spec is genuinely done.
<p class="lede">The one-line summary prune lifts into the live list. Not a meta, but required in practice.

Writing a new spec: copy the <head> from any file in specs/, link spec.css, write semantic HTML, declare the metadata, give it a lede. Then run ./specs.sh prune.
